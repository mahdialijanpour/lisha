# لیشا — React + Vite

فروشگاه فارسی و راست‌به‌چپ با رنگ بنفش لیشا و چیدمان الهام‌گرفته از للفی.

## اجرا

```sh
npm install
npm run dev
npm run build
npm test
```

## امکانات

- خانه، فروشگاه، دسته‌بندی، محصول، چاپ دلخواه، سبد، بررسی و ارسال درخواست چاپ، رسید سرور، پروفایل محلی، علاقه‌مندی، درباره، تماس، FAQ، نظرات و مجله.
- جستجو و مرتب‌سازی، انتخاب سایز و تعداد، سبد پایدار در مرورگر.
- عکس‌های شفاف PNG از جلو، پشت و کنار دورس و هودی بدون بند؛ چهار نما با کلید و کشیدن قابل تغییرند. این نمایش چهار عکس ثابت است و مدل سه‌بعدی یا چرخش پیوستهٔ ۳۶۰ درجه نیست.
- شش رنگ شامل سورمه‌ای و قهوه‌ای؛ محل‌های از پیش تعیین‌شده برای سینه، جیب، پشت، بالا/وسط/پایین هر آستین و سه محل کلاه. گزینه دو طرف کلاه دو چاپ مستقل می‌سازد. اندازه‌ها سانتی‌مترند و نسبت تصویر حفظ می‌شود.
- آپلود فایل اصلی تا ۱۰ مگابایت، نسخه سبک جداگانه، ثبت درخواست در سرور، رسید مشتری و برگه چاپ خوانا.
- طراحی واکنش‌گرا، هدر شیشه‌ای با انیمیشن اتصال و لوگوی کوچک، دیالوگ قابل استفاده با صفحه‌کلید و پشتیبانی از کاهش حرکت.
- راهنمای فایل چاپ، جای طرح، جدول سایز نمونه و نگهداری لباس در پایین استودیوی چاپ دلخواه.

## پیش از فروش واقعی

API ثبت درخواست و ذخیره فایل فعال است. پرداخت، موجودی، ارسال، احراز هویت حساب و پنل مدیریت تجاری هنوز متصل نیستند. قیمت‌ها و اندازه‌های لباس و محل چاپ، نمونه‌اند. هر درخواست با وضعیت `pending_print_review` و `productionApproved: false` ثبت می‌شود؛ کالیبراسیون با لباس واقعی، روش چاپ و هزینه‌های نهایی باید پیش از تولید تأیید شوند.

## بک‌اند و اطلاعات چاپ

در توسعه، همان `npm run dev` هم React و هم مسیرهای `/api` را اجرا می‌کند. برای استقرار با بک‌اند:

```sh
npm run build
npm start
```

پورت پیش‌فرض production برابر ۳۰۰۰ است. `PORT`، `HOST` و `LISHA_DATA_DIR` قابل تنظیم‌اند. Docker اکنون Node را اجرا می‌کند؛ برای حفظ فایل‌ها volume پوشه `/app/data` باید پایدار باشد. هاست صرفاً استاتیک برای آپلود و ثبت درخواست کافی نیست.

- `POST /api/print-assets`: JSON شامل `fileName`، فایل اصلی `original` و `preview` با Data URL؛ PNG/JPEG/WebP پذیرفته می‌شوند. فایل اصلی بدون تغییر بایت ذخیره می‌شود. سرور نوع، حجم، ابعاد، جهت EXIF برای JPEG و SHA-256 را استخراج می‌کند. پیش‌نمایش سقف ۷۵۰ کیلوبایت دارد.
- `POST /api/orders`: `idempotencyKey`، `confirmed`، `customer: {name, phone, note}` و `items: [{productId, qty, size, custom?}]`. اطلاعات سفارشی شامل `schemaVersion: 3`، `kind`، `colorId`، `note` و `placements: [{slotId, assetId, widthCm}]` است. قرارداد در `shared/print-spec.js` تعریف شده است.
- قیمت، SKU، نام رنگ و کد HEX، ارتفاع با حفظ نسبت، قسمت و محل چاپ، مختصات مرکز نسبت به درز مرجع، واحد cm، جهت از دید پوشنده، زاویه، سایز لباس، فایل اصلی، پیکسل، DPI و checksum در سرور از نو ساخته و در سفارش ثبت می‌شوند. مختصات و قیمت ارسالی کلاینت قابل اعتماد فرض نمی‌شوند.
- `GET /api/orders` و `GET /api/orders/:id`: درخواست‌ها و رسید کامل همان نشست. `GET /api/orders/:id/print`: برگه HTML قابل چاپ. دریافت اصل و پیش‌نمایش از `/api/print-assets/:id/original` و `/preview`.
- نشست تصادفی در کوکی HttpOnly و SameSite=Strict نگه داشته می‌شود. مشتری دیگری به فایل و رسید دسترسی ندارد. پاک شدن کوکی دسترسی مرورگر را از بین می‌برد؛ بازیابی با شماره تلفن هنوز وجود ندارد. برای انتشار، HTTPS و پشتیبان‌گیری از داده لازم است.

سفارش‌ها در `data/orders/LS-….json`، برگه خوانای چاپ در فایل هم‌نام `.print.html` و اصل طرح‌ها در `data/assets/` ذخیره می‌شوند. صاحب فروشگاه می‌تواند فایل HTML را محلی باز کند و تمام جزئیات و لینک فایل اصلی را ببیند. این مسیرها از وب عمومی قابل مرور نیستند. داده‌های مشتری در Git و Docker context قرار نمی‌گیرند. ثبت تکراری با همان کلید، حتی بعد از راه‌اندازی مجدد، همان رسید را برمی‌گرداند. سبد فقط بعد از پاسخ موفق سرور پاک می‌شود.

موقعیت‌های نسخه `reference-1` پیش‌فرض نمونه‌اند؛ پیش از تولید باید با مدل و سایز واقعی تأمین‌کننده کالیبره شوند. مبدأ هر چاپ نام درز مرجع است؛ x مثبت به چپ پوشنده و y مثبت به سمت پایین لباس است، و مختصات به **مرکز طرح** اشاره می‌کنند. طرح قدیمی فاقد فایل اصلی، هنگام ارسال رد می‌شود و باید دوباره بارگذاری شود.


## منابع

- تصاویر شش هودی: پوشه artwork در چت «چاپ همه طرح‌ها روی هودی مشکی»؛ فایل‌های اصلی دست‌نخورده باقی مانده‌اند.
- تصویر هرو و توت‌بگ: تولید اختصاصی با ابزار داخلی imagegen؛ تصویر توت‌بگ نمونه‌ی طراحی است.
- عکس‌های خام لباس با ابزار داخلی Imagegen تولید شدند. شش فایل شفاف در `public/assets/{sweatshirts,hoodies}-{front,back,side}.png` قرار دارند. نمای سمت چپ با قرینه‌کردن تنها عکس پایه از نمای کنار نمایش داده می‌شود؛ نوشته و طرح قرینه نمی‌شوند. پرامپت‌های اصلی در `scripts/blank-garment-prompts.json` و نماهای تازه در `scripts/photo-view-prompts.json` ثبت شده‌اند. رندر فعلی عکس در `src/photo-print-viewer.jsx` است؛ فایل‌های WebGL قدیمی در مسیر فعال سایت استفاده نمی‌شوند.
- خروجی‌های بهینه‌شده در `public/assets/hero.webp` و `public/assets/tote.webp`؛ متن کامل پرامپت‌ها در `scripts/image-prompts.json` است. نسخه‌های اصلی در `assets-original/` نگه‌داری شده‌اند.
- لوگوی فعلی Lisha space: بازطراحی گل‌دار از طرح اولیه کاربر با Imagegen؛ فایل اصلی شفاف در `public/assets/lishaspace-botanical-v2.png` و نسخه سبک وب در فایل WebP هم‌نام. استایل هدر و فوتر در `src/branding.css` است. گل خندان و تصویر دورس همچنان SVG اختصاصی پروژه هستند.
- فونت تیتر Pofak از فایل عمومی سایت مرجع lelefi.com مطابق درخواست کاربر؛ وضعیت مجوز وب برای انتشار تجاری باید با صاحب فونت بررسی شود. فونت متن Vazirmatn از Google Fonts.
- صفحه اینستاگرام از سایت فعلی لیشا: https://instagram.com/lishacrafts

پالت و چیدمان پایه در `src/styles.css`، ظاهر جدید کارت‌ها و منوی راست‌به‌چپ در `src/refinements.css`، صفحه محصول و رسید سبد در `src/shopping.css`، منو و سبد شناور در `src/navigation.jsx`، محصولات در `src/data.js` و مسیرها در `src/main.jsx` قابل تغییرند.

## بررسی انجام‌شده

بیلد production و ۱۴ بررسی خودکار منطق سبد، محدوده‌های چاپ و API پاس شده‌اند. تست API، اصل فایل را بایت‌به‌بایت مقایسه می‌کند و ثبت جزئیات، قیمت سرور، بازیابی پس از راه‌اندازی دوباره، ارسال تکراری، رد اندازه نامعتبر و جداسازی نشست‌ها را بررسی می‌کند. مسیر واقعی بارگذاری → پنج محل چاپ → سبد → ارسال درخواست → رسید سرور در مرورگر آزمایش شده و نمای موبایل ۳۹۰ پیکسلی بررسی شده است. داده تست رابط در `.sites-local/qa-print-data` جدا از سفارش‌های سایت نگه داشته می‌شود.

پروژه فعلاً روی سرور محلی اجراست. نسخه آنلاین منتشر نشده است؛ تنظیمات قبلی Sites در `.openai/hosting.json` حفظ شده است. برای این نسخهٔ دارای بک‌اند، استقرار Node و فضای داده پایدار نیاز است.
